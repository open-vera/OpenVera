## 1. 产品概述

### 1.1 产品定位

TaskFlow 是一款轻量级个人任务管理 Web 应用，定位于"过于复杂的项目管理工具（Jira/Asana）"与"功能单薄的纯文本备忘录"之间，面向个人用户和 2-5 人的小型团队，提供简洁但功能完备的任务管理体验。

### 1.2 目标用户

| 用户群体 | 画像描述 | 核心痛点 |
|----------|----------|----------|
| 个人开发者 | 管理多个并行项目的开发任务 | 需要快速录入、不被工具打断工作流 |
| 自由职业者 | 同时服务多个客户，需追踪交付进度 | 需要按客户/项目分类管理任务 |
| 小型团队成员 | 2-5 人协作，任务需透明可追踪 | 现有工具太重，学习成本高 |
| 知识工作者 | 日常有大量待办事项需结构化管理 | 纯文本备忘录无法设置优先级和截止日期 |

### 1.3 核心价值主张

**用最少的操作步骤完成任务的录入、追踪和归档，保持界面清爽不干扰。**

### 1.4 成功指标

| 指标 | 目标值 |
|------|--------|
| 页面首次加载时间 | < 2 秒（本地环境） |
| API 接口响应时间 | < 200ms（单用户场景） |
| 最大任务承载量 | ≥ 500 条无明显性能下降 |
| 单元测试覆盖率 | ≥ 70% |
| P0 级别缺陷 | 0 |

### 2.2 P0 功能详细定义

#### F01 用户注册与登录

**功能描述**: 用户通过邮箱和密码注册账号，登录后获取 JWT Token，后续请求携带 Token 进行身份验证。

**详细需求**:

| 项目 | 说明 |
|------|------|
| 注册表单字段 | 邮箱（必填，唯一）、密码（必填，≥8 位）、确认密码 |
| 登录表单字段 | 邮箱、密码 |
| 密码安全 | 使用 bcrypt 进行密码哈希存储，不存储明文密码 |
| 认证方式 | JWT（JSON Web Token），Token 包含用户 ID 和过期时间 |
| 会话管理 | Token 过期后自动跳转登录页；支持手动退出登录 |
| 错误处理 | 注册时邮箱重复提示"该邮箱已被注册"；登录失败提示"邮箱或密码错误" |

**验收标准**:

- [ ] AC-F01-1: 用户输入有效邮箱和 ≥8 位密码后点击注册，系统创建账号并跳转到登录页
- [ ] AC-F01-2: 注册时输入已存在的邮箱，系统显示"该邮箱已被注册"错误提示
- [ ] AC-F01-3: 注册时密码少于 8 位，系统显示密码长度不满足要求的提示
- [ ] AC-F01-4: 注册时两次密码不一致，系统显示确认密码不匹配提示
- [ ] AC-F01-5: 用户输入正确邮箱和密码登录后，获得有效 JWT Token 并跳转到任务列表页
- [ ] AC-F01-6: 用户输入错误密码登录，系统显示"邮箱或密码错误"提示
- [ ] AC-F01-7: Token 过期后，用户发起请求时被重定向到登录页
- [ ] AC-F01-8: 用户点击退出登录后，Token 被清除并跳转到登录页
- [ ] AC-F01-9: 数据库中密码以 bcrypt 哈希形式存储，不可反向解密

**边界条件与异常场景**:

- 邮箱格式校验（前端 + 后端双重校验）
- 并发注册相同邮箱的竞态处理
- Token 在多设备登录时的行为（本期允许覆盖旧 Token）
- 密码输入框需有显示/隐藏切换功能

#### F02 任务 CRUD

**功能描述**: 用户可创建、查看、编辑和删除任务。每条任务包含标题、描述、优先级、截止日期和状态。

**详细需求**:

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| 标题 | string | ✅ | 1-200 字符 |
| 描述 | string | ❌ | 最大 2000 字符，支持换行 |
| 优先级 | enum | ✅ | high / medium / low，默认 medium |
| 截止日期 | date | ❌ | 日期选择器，不能选择过去日期（创建时） |
| 状态 | enum | ✅ | todo / in_progress / completed，默认 todo |
| 创建时间 | datetime | 自动 | 系统自动生成 |
| 更新时间 | datetime | 自动 | 系统自动更新 |

**验收标准**:

- [ ] AC-F02-1: 用户填写标题后点击创建，任务被成功创建并出现在列表中
- [ ] AC-F02-2: 用户可以同时填写标题、描述、优先级、截止日期来创建完整任务
- [ ] AC-F02-3: 标题为空时点击创建，系统显示"标题不能为空"错误提示
- [ ] AC-F02-4: 标题超过 200 字符时，系统显示字符数超限提示
- [ ] AC-F02-5: 用户点击某条任务可查看详情页面，显示所有字段信息
- [ ] AC-F02-6: 用户在详情页或列表中点击编辑，可修改任务的标题、描述、优先级、截止日期
- [ ] AC-F02-7: 编辑后保存，列表中任务信息同步更新
- [ ] AC-F02-8: 用户点击删除任务，系统弹出确认对话框"确定要删除此任务？"
- [ ] AC-F02-9: 用户确认删除后，任务从列表中移除
- [ ] AC-F02-10: 用户取消删除操作，任务保持不变

**边界条件与异常场景**:

- 任务被删除后无法恢复（本期不做回收站）
- 编辑任务时如果已被其他会话删除，给出友好提示
- 截止日期字段支持清空（设为无截止日期）
- 创建时间由服务端生成，不允许客户端篡改

#### F03 任务列表与筛选

**功能描述**: 以列表形式展示用户的所有任务，支持按状态和优先级进行多维度筛选，支持按截止日期排序。

**详细需求**:

| 筛选维度 | 选项 |
|----------|------|
| 状态 | 全部 / 待办 / 进行中 / 已完成 |
| 优先级 | 全部 / 高 / 中 / 低 |
| 排序 | 截止日期升序（最近到期优先）/ 截止日期降序 / 创建时间倒序（默认） |

**验收标准**:

- [ ] AC-F03-1: 用户进入任务列表页，默认显示所有任务，按创建时间倒序排列
- [ ] AC-F03-2: 用户选择状态筛选为"待办"，列表只显示状态为待办的任务
- [ ] AC-F03-3: 用户同时设置状态筛选"进行中"和优先级"高"，列表显示同时满足两个条件的任务
- [ ] AC-F03-4: 用户清除所有筛选条件，列表恢复显示全部任务
- [ ] AC-F03-5: 用户选择"截止日期升序"排序，任务按最近到期的排在最前面
- [ ] AC-F03-6: 无截止日期的任务排在有截止日期的任务之后
- [ ] AC-F03-7: 筛选结果为空时，显示"暂无任务"空状态提示
- [ ] AC-F03-8: 任务数量较多时（超过 50 条），支持分页加载（每页 20 条）

**边界条件与异常场景**:

- 筛选和排序状态在页面刷新后保持（通过 URL 参数或本地存储）
- 0 条任务时显示引导创建任务的空状态页面
- 大量任务时使用分页避免一次性加载过多数据

#### F04 任务状态流转

**功能描述**: 任务支持三种状态：待办（todo）→ 进行中（in_progress）→ 已完成（completed），支持一键状态切换。

**详细需求**:

- 状态流转方向：todo → in_progress → completed（正向），也支持回退：completed → in_progress → todo
- 列表中每个任务的状态可通过点击状态徽章/按钮一键切换
- 状态变更后立即生效，无需手动保存
- 已完成的任务在视觉上有明显区分（如划线、灰色、置底等）

**验收标准**:

- [ ] AC-F04-1: 用户点击状态为"待办"的任务状态按钮，状态变为"进行中"
- [ ] AC-F04-2: 用户点击状态为"进行中"的任务状态按钮，状态变为"已完成"
- [ ] AC-F04-3: 用户点击状态为"已完成"的任务状态按钮，状态回退为"待办"
- [ ] AC-F04-4: 状态变更后无需手动保存，立即显示新状态
- [ ] AC-F04-5: 已完成的任务在列表中有视觉区分（如文字划线、灰色背景等）
- [ ] AC-F04-6: 状态变更操作记录更新时间（自动更新 updated_at 字段）

**边界条件与异常场景**:

- 网络异常时状态变更失败，应恢复为原状态并提示用户
- 快速连续点击状态按钮，应防抖处理避免重复请求
- 状态变更采用乐观更新（先改 UI 再发请求），失败时回滚

#### F05 响应式 Web 界面

**功能描述**: 应用界面适配桌面端和移动端浏览器，提供一致的使用体验。

**详细需求**:

| 断点 | 宽度范围 | 布局策略 |
|------|----------|----------|
| 桌面端 | ≥ 1024px | 侧边栏 + 主内容区，表格/卡片视图 |
| 平板端 | 768px - 1023px | 可折叠侧边栏，适度压缩布局 |
| 移动端 | < 768px | 底部导航或汉堡菜单，单列布局 |

**验收标准**:

- [ ] AC-F05-1: 在 1920×1080 桌面浏览器中，页面布局正常，无溢出或重叠
- [ ] AC-F05-2: 在 768×1024 平板浏览器中，侧边栏可折叠，内容区自适应宽度
- [ ] AC-F05-3: 在 375×812 移动浏览器中，导航折叠为汉堡菜单，内容单列显示
- [ ] AC-F05-4: 所有表单在移动端可正常填写和提交
- [ ] AC-F05-5: 所有按钮和可点击元素在移动端的触控区域不小于 44×44px
- [ ] AC-F05-6: 文字在各尺寸下可读，最小字号不小于 14px

**边界条件与异常场景**:

- 横竖屏切换时布局平滑过渡
- 极窄屏幕（< 320px）不崩溃但可能有横向滚动

### 2.3 P1 功能详细定义

#### F06 任务分类（标签系统）

**功能描述**: 用户可为任务添加多个自定义标签，支持按标签筛选任务。

**验收标准**:

- [ ] AC-F06-1: 用户创建任务时可添加一个或多个标签
- [ ] AC-F06-2: 标签名称不超过 20 字符，支持中文和英文
- [ ] AC-F06-3: 同一任务下不允许添加重复标签
- [ ] AC-F06-4: 用户可从已有标签中选择或创建新标签
- [ ] AC-F06-5: 列表页支持按标签筛选，选中标签后只显示含该标签的任务
- [ ] AC-F06-6: 用户可删除任务上的标签，不影响其他任务的同名标签
- [ ] AC-F06-7: 标签管理页面支持查看所有标签及其关联的任务数量

**边界条件**:

- 单个任务最多关联 10 个标签
- 删除标签时仅移除关联关系，不删除标签本身（P1 简化处理）
- 标签名前后自动去空格

#### F07 任务搜索

**功能描述**: 支持按任务标题和描述进行关键词全文搜索。

**验收标准**:

- [ ] AC-F07-1: 用户在搜索框输入关键词，列表实时显示匹配结果（防抖 300ms）
- [ ] AC-F07-2: 搜索结果同时匹配标题和描述中的关键词
- [ ] AC-F07-3: 搜索支持部分匹配（模糊搜索）
- [ ] AC-F07-4: 搜索不区分大小写
- [ ] AC-F07-5: 搜索框清空后恢复显示全部任务
- [ ] AC-F07-6: 无匹配结果时显示"未找到相关任务"提示
- [ ] AC-F07-7: 搜索结果可与状态/优先级筛选叠加使用

**边界条件**:

- 搜索框输入纯空格时视为无搜索条件
- 超长关键词（>100 字符）截断处理
- 搜索词高亮显示匹配文本（Nice to have）

#### F08 任务统计仪表盘

**功能描述**: 以图表或卡片形式展示任务的整体统计数据。

**验收标准**:

- [ ] AC-F08-1: 显示任务总数
- [ ] AC-F08-2: 显示各状态（待办/进行中/已完成）的任务数量和占比

**边界条件**:

- "本周"的定义：周一 00:00 至周日 23:59
- 无截止日期的任务不纳入"本周到期"和"逾期"统计
- 仪表盘页面加载时间 < 500ms

## 3. 非功能需求

### 3.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面首次加载 | < 2 秒（本地环境） |
| API 响应时间 | < 200ms（单用户场景） |
| 任务承载量 | 500 条任务无明显性能下降 |
| 搜索响应 | < 300ms（含网络延迟） |

### 3.2 安全要求

| 安全项 | 要求 |
|--------|------|
| 密码存储 | bcrypt 哈希，cost factor ≥ 10 |
| 认证 | JWT Token，有效期 ≤ 24 小时 |
| 输入校验 | 前后端双重校验，防 XSS 和 SQL 注入 |
| 权限隔离 | 用户只能访问自己的任务，不能查看/修改他人数据 |
| API 鉴权 | 所有任务相关 API 需携带有效 Token |

### 3.3 可用性要求

- 所有表单操作有明确的成功/失败反馈
- 关键操作（删除）需二次确认
- 页面加载中显示加载状态指示器
- 空状态页面提供引导操作

### 3.4 可维护性要求

- 代码规范：ESLint + Prettier
- 有意义的 Git 提交信息
- 核心功能单元测试覆盖率 ≥ 70%
- 附带 README.md（项目介绍、运行步骤、API 概览）

| 层级 | 技术选型 |
|------|----------|
| 前端框架 | React 18 + TypeScript |

## 5. MVP 范围定义

### 5.1 MVP 包含

MVP 严格限定为 **P0 功能（F01-F05）**：

1. ✅ 用户注册与登录（邮箱/密码 + JWT 认证）
2. ✅ 任务 CRUD（创建、查看、编辑、删除）
3. ✅ 任务列表与筛选（状态、优先级筛选 + 排序 + 分页）
4. ✅ 任务状态流转（待办→进行中→已完成）
5. ✅ 响应式 Web 界面（桌面 + 移动端适配）

### 5.2 MVP 不包含

- 标签系统（P1）
- 搜索功能（P1）
- 统计仪表盘（P1）
- 拖拽排序（P2）
- 批量操作（P2）
- 深色模式（P2）
- P3 全部功能

### 5.3 MVP 验收条件

MVP 交付时需满足：

1. 用户可注册、登录、退出，Token 过期自动跳转登录
2. 用户可创建、查看、编辑、删除自己的任务
3. 任务列表支持按状态/优先级筛选，按日期排序
4. 任务状态可通过点击一键流转
5. 在桌面和移动浏览器中均可正常使用全部功能
6. API 响应时间 < 200ms，500 条任务不卡顿
7. 核心功能单元测试覆盖率 ≥ 70%
8. 无 P0 级别缺陷

## 6. 数据模型概要

### 6.1 用户表 (users)

| 字段 | 类型 | 约束 |
|------|------|------|
| id | TEXT (UUID) | PK |
| email | TEXT | UNIQUE, NOT NULL |
| password_hash | TEXT | NOT NULL |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP |

### 6.2 任务表 (tasks)

| 字段 | 类型 | 约束 |
|------|------|------|
| id | TEXT (UUID) | PK |
| user_id | TEXT | FK → users.id, NOT NULL |
| title | TEXT | NOT NULL, 1-200 字符 |
| description | TEXT | 可空, 最大 2000 字符 |
| priority | TEXT | CHECK (high/medium/low), DEFAULT 'medium' |
| status | TEXT | CHECK (todo/in_progress/completed), DEFAULT 'todo' |
| due_date | DATE | 可空 |
| sort_order | INTEGER | 排序权重 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP |

### 6.3 标签表 (tags) — P1

| 字段 | 类型 | 约束 |
|------|------|------|
| id | TEXT (UUID) | PK |
| user_id | TEXT | FK → users.id |
| name | TEXT | NOT NULL, 1-20 字符 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP |

### 6.4 任务-标签关联表 (task_tags) — P1

| 字段 | 类型 | 约束 |
|------|------|------|
| task_id | TEXT | FK → tasks.id, PK |
| tag_id | TEXT | FK → tags.id, PK |
