| 建议 | 采纳决策 | 理由 |

## 7. MVP 范围定义

### MVP 包含（P0 严格交付）

1. ✅ **用户注册与登录** — 邮箱/密码注册，JWT 认证，会话管理，Token 过期处理
2. ✅ **任务 CRUD** — 创建、查看、编辑、删除任务（标题、描述、优先级、截止日期、状态）
3. ✅ **任务列表与筛选** — 按状态/优先级多维筛选，按截止日期排序，分页加载
4. ✅ **任务状态流转** — 待办→进行中→已完成，一键切换，乐观更新
5. ✅ **响应式 Web 界面** — 桌面（≥1024px）/ 平板（768-1023px）/ 移动端（<768px）三断点适配

### MVP 验收条件

1. 用户可注册、登录、退出，Token 过期自动跳转登录
2. 用户可创建、查看、编辑、删除自己的任务
3. 任务列表支持按状态/优先级筛选，按日期排序
4. 任务状态可通过点击一键流转
5. 在桌面和移动浏览器中均可正常使用全部功能
6. API 响应时间 < 200ms，500 条任务不卡顿
7. 核心功能单元测试覆盖率 ≥ 70%
8. 无 P0 级别缺陷

## 13. 给下一步（方案设计）的指导

### 13.1 架构设计要点

- 前后端分离架构，前端 React SPA + 后端 RESTful API
- SQLite 数据库设计应预留 tags / task_tags 表结构，避免后续大改
- JWT Token 存储使用 localStorage（MVP 简化），后续可迁移 httpOnly cookie

### 13.2 前端设计要点

- 任务状态切换使用乐观更新策略（先改 UI 再发请求，失败回滚）
- 搜索功能需实现 300ms 防抖
- 三个响应式断点的布局方案需在 UI 设计阶段明确
- 移动端使用浮动操作按钮（FAB）方便快速创建任务
- 空状态和加载状态的 UI 设计不要遗漏

### 13.3 后端设计要点

- 任务列表接口支持 `status`、`priority`、`sort`、`page`、`pageSize` 等 query 参数
- 搜索采用 SQLite LIKE 查询（P1 简化）或 FTS5（性能更好）
- 统一错误响应格式：`{ error: { code, message } }`
- CORS 配置需区分开发（Vite dev server）和生产（同源）环境

### 13.4 安全设计要点

- 密码 bcrypt 哈希存储，cost factor ≥ 10
- 所有任务相关 API 需 JWT 鉴权中间件
- 输入校验前后端双重实现
- 用户只能操作自己的任务数据（user_id 隔离）
