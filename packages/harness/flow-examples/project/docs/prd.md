## 1. 产品概述

### 1.1 产品定位

TaskFlow 是一款**轻量级个人任务管理 Web 应用**，面向个人开发者、自由职业者和 2-5 人小型团队，提供简洁但功能完备的待办事项管理能力。

### 1.2 核心价值主张

> 用最少的操作步骤完成任务的录入、追踪和归档，保持界面清爽不干扰。

### 1.3 目标用户画像

| 用户角色 | 场景 | 痛点 |
|---------|------|------|
| 个人开发者 | 管理日常开发任务和学习计划 | Jira 过重，纯文本无法追踪状态 |
| 自由职业者 | 同时跟进多个客户项目 | 缺乏结构化的任务分类和优先级管理 |
| 小型团队成员 | 2-5 人协作管理共享待办 | 不想为简单需求搭建复杂项目管理系统 |

### 1.4 竞品对比分析

| 特性 | TaskFlow | Todoist | Trello | Jira |
|------|----------|---------|--------|------|
| 上手难度 | ⭐ 极简 | ⭐⭐ 简单 | ⭐⭐ 中等 | ⭐⭐⭐ 复杂 |
| 任务状态流转 | ✅ 三态 | ❌ 二态 | ✅ 看板 | ✅ 自定义 |
| 标签系统 | ✅ | ✅ | ✅ | ✅ |
| 自部署 | ✅ | ❌ | ❌ | ✅（重型）|
| 移动端适配 | ✅ 响应式 | ✅ 原生 | ✅ 原生 | ✅ 原生 |
| 数据隐私 | ✅ 本地 | ❌ 云端 | ❌ 云端 | ✅ 可自托管 |
| 价格 | 免费开源 | 免费/付费 | 免费/付费 | 付费 |

**TaskFlow 差异化优势**：自部署 + 轻量 + 数据隐私 + 开源免费，填补「过于复杂」和「功能单薄」之间的空白。

### 2.2 P0 功能详细定义（MVP）

#### F01 用户注册与登录

**功能描述**：支持用户通过邮箱和密码注册账号，登录后获取 JWT 令牌进行身份认证。

**详细需求**：

| 项目 | 说明 |
|------|------|
| 注册表单 | 邮箱（必填，格式校验）、密码（必填，≥ 8 位，含大小写字母和数字）、确认密码 |
| 登录表单 | 邮箱 + 密码 |
| 认证方式 | JWT（JSON Web Token），Access Token 有效期 24 小时 |
| 密码存储 | bcrypt 哈希加密，salt rounds ≥ 10 |
| 会话管理 | Token 存储于 localStorage，过期后自动跳转登录页 |
| 错误处理 | 邮箱已注册、密码错误、Token 过期等场景均需友好提示 |

**验收标准**：
- [ ] 用户可通过邮箱和密码成功注册
- [ ] 注册时密码强度不足给出明确提示
- [ ] 用户登录后获取有效 JWT Token
- [ ] Token 过期后自动跳转登录页
- [ ] 未登录状态访问受保护页面被重定向至登录页
- [ ] 密码以 bcrypt 哈希形式存储，不存明文

---

#### F02 任务 CRUD

**功能描述**：支持任务的创建、查看、编辑和删除，每条任务包含完整的属性信息。

**任务数据模型**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | UUID | 自动 | 任务唯一标识 |
| title | string | ✅ | 任务标题，1-200 字符 |
| description | string | ❌ | 任务描述，支持多行文本，最长 2000 字符 |
| priority | enum | ✅ | 优先级：high / medium / low，默认 medium |
| status | enum | 自动 | 状态：todo / in_progress / completed，默认 todo |
| due_date | date | ❌ | 截止日期，YYYY-MM-DD 格式 |
| created_at | timestamp | 自动 | 创建时间 |
| updated_at | timestamp | 自动 | 更新时间 |
| user_id | UUID | 自动 | 所属用户 ID |

**操作行为**：

| 操作 | 入口 | 行为 |
|------|------|------|
| 创建 | 列表页顶部「新建任务」按钮 | 弹出模态框或内联表单，填写后提交 |
| 查看 | 点击任务标题 | 展开/跳转任务详情 |
| 编辑 | 任务详情页「编辑」按钮 | 进入编辑模式，修改后保存 |
| 删除 | 任务详情或列表中「删除」按钮 | 二次确认后删除，不可恢复 |

**验收标准**：
- [ ] 用户可以创建包含标题、描述、优先级、截止日期的任务
- [ ] 创建时标题为必填，其他字段可选
- [ ] 创建成功后任务出现在列表中，状态默认为「待办」
- [ ] 可以查看任务详情，展示所有字段
- [ ] 可以编辑任务的所有可变字段（标题、描述、优先级、截止日期）
- [ ] 删除操作有二次确认弹窗，确认后任务被永久删除
- [ ] 非本人任务无法进行编辑/删除操作（权限隔离）
- [ ] 标题为空或超长时给出校验提示

#### F03 任务列表与筛选

**功能描述**：以列表形式展示当前用户的全部任务，支持按状态、优先级筛选和按截止日期排序。

**列表展示**：
- 每条任务展示：标题、优先级标识（颜色/图标）、状态标签、截止日期
- 默认按创建时间倒序排列
- 支持按截止日期升序/降序排序

**筛选功能**：

| 筛选维度 | 可选值 | 默认值 |
|---------|--------|--------|
| 状态 | 全部 / 待办 / 进行中 / 已完成 | 全部 |
| 优先级 | 全部 / 高 / 中 / 低 | 全部 |
| 排序方式 | 创建时间（降序）/ 截止日期（升序/降序）| 创建时间降序 |

**验收标准**：
- [ ] 列表正确展示所有任务的基本信息
- [ ] 按状态筛选后只显示匹配状态的任务
- [ ] 按优先级筛选后只显示匹配优先级的任务
- [ ] 多个筛选条件可以组合使用（AND 关系）
- [ ] 切换排序方式后列表顺序立即更新
- [ ] 筛选条件变更后保持在 URL 中，支持页面刷新后恢复
- [ ] 列表为空时展示友好的空状态提示

#### F04 任务状态流转

**功能描述**：任务具有三个状态（待办 → 进行中 → 已完成），支持一键切换和状态流转。

**状态定义**：

| 状态 | 标识 | 显示名 | 说明 |
|------|------|--------|------|
| 待办 | todo | 待办 | 新建任务默认状态 |
| 进行中 | in_progress | 进行中 | 任务正在执行 |
| 已完成 | completed | 已完成 | 任务已完结 |

**状态流转规则**：
- 待办 → 进行中（一键操作）
- 进行中 → 已完成（一键操作）
- 已完成 → 待办（重开任务）
- 已完成 → 进行中（重开到进行中）
- 待办 → 已完成（直接完成，快捷操作）

**交互方式**：
- 列表中每个任务旁有状态切换按钮/下拉菜单
- 支持点击快速切换到下一个状态
- 状态变更后即时反映在界面上（乐观更新）

**验收标准**：
- [ ] 新建任务默认状态为「待办」
- [ ] 点击状态按钮可以切换到下一个状态
- [ ] 可以通过下拉菜单选择任意目标状态
- [ ] 「已完成」任务视觉上有明显区分（如划线、灰色）
- [ ] 状态变更即时生效，无需手动刷新
- [ ] 支持「重开」已完成的任务
- [ ] 状态变更记录 updated_at 时间戳更新

#### F05 响应式 Web 界面

**功能描述**：界面适配桌面和移动端浏览器，提供一致的使用体验。

**布局规格**：

| 断点 | 宽度 | 布局策略 |
|------|------|---------|
| 桌面 | ≥ 1024px | 多列布局，侧边栏 + 主内容区 |
| 平板 | 768px - 1023px | 折叠侧边栏，主内容区全宽 |
| 手机 | < 768px | 单列布局，底部导航栏 |

**性能要求**：
- 首次加载时间 < 2 秒（本地环境）
- 交互操作响应 < 100ms
- 支持 500 条任务列表无明显卡顿（虚拟滚动或分页）

**验收标准**：
- [ ] 桌面端（≥ 1024px）展示完整的侧边栏 + 主内容区布局
- [ ] 平板端（768px - 1023px）侧边栏可折叠
- [ ] 移动端（< 768px）切换为单列布局
- [ ] 所有功能在三种断点下均可正常使用
- [ ] 触摸设备上的按钮尺寸 ≥ 44px × 44px（触摸友好）
- [ ] 首屏加载时间 < 2 秒

### 2.3 P1 功能详细定义

#### F06 任务分类（标签系统）

**功能描述**：支持为任务添加多个自定义标签，通过标签对任务进行分类和筛选。

**标签数据模型**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 标签唯一标识 |
| name | string | 标签名，1-50 字符，同一用户下唯一 |
| color | string | 标签颜色，HEX 色值 |
| user_id | UUID | 所属用户 |

**功能细节**：
- 每个任务可添加 0~10 个标签
- 创建任务时可选标签，也可在编辑时添加/移除
- 支持创建新标签（输入标签名 + 选择颜色）
- 列表筛选增加「标签」维度，支持多标签筛选

**验收标准**：
- [ ] 可以创建自定义标签（名称 + 颜色）
- [ ] 可以为任务添加/移除标签
- [ ] 每个任务最多关联 10 个标签
- [ ] 标签在同一用户名下不重名
- [ ] 可以按标签筛选任务列表
- [ ] 标签以彩色胶囊样式展示在任务卡片上

---

#### F07 任务搜索

**功能描述**：支持按标题和描述进行关键词全文搜索。

**功能细节**：
- 搜索入口固定在页面顶部
- 输入关键词后实时搜索（debounce 300ms）
- 搜索范围：当前用户的任务标题和描述
- 搜索结果高亮匹配关键词
- 搜索可与筛选条件组合使用

**验收标准**：
- [ ] 输入关键词后 300ms 内发起搜索请求
- [ ] 搜索结果包含标题或描述中匹配关键词的任务
- [ ] 匹配关键词在结果中高亮显示
- [ ] 搜索无结果时展示友好提示
- [ ] 搜索条件可与状态/优先级筛选组合

**统计指标**：

| 指标 | 说明 |
|------|------|
| 总任务数 | 当前用户所有任务数量 |
| 待办数量 | 状态为 todo 的任务数 |

| 本周到期任务数 | 截止日期在本周内的未完成任务数 |
| 逾期任务数 | 截止日期已过且未完成的任务数 |

**验收标准**：
- [ ] 展示正确的任务总数和各状态数量
- [ ] 展示本周到期任务数和逾期任务数
- [ ] 统计数据与任务列表实时同步（增删改后自动更新）
- [ ] 使用可视化图表（如环形图/柱状图）展示状态分布

## 5. MVP 范围定义

### MVP（P0 功能集）必须包含：

1. ✅ 用户注册与登录（JWT 认证）
2. ✅ 任务的创建、查看、编辑、删除
3. ✅ 任务列表展示 + 按状态/优先级筛选 + 按日期排序
4. ✅ 任务状态流转（待办 ↔ 进行中 ↔ 已完成）
5. ✅ 响应式布局（桌面 + 移动端）

### MVP 不包含：

- 标签系统（P1）
- 搜索功能（P1）
- 统计仪表盘（P1）
- 拖拽排序（P2）
- 批量操作（P2）
- 深色模式（P2）
- 多人协作/附件/通知（P3）

### MVP 验收总标准：

- 所有 P0 功能的验收标准全部通过
- 无 P0 级别缺陷
- 核心功能测试覆盖率 ≥ 70%
- 可通过 `npm start` 一键启动并正常使用

## 8. 附录

### 8.1 术语表

| 术语 | 定义 |
|------|------|
| MVP | Minimum Viable Product，最小可行产品 |
| JWT | JSON Web Token，用于无状态身份认证 |
