# 音频转写标注与质检 — 业界方案调研

> 整理业界在音频转写标注和质检各环节的主流技术方案，作为本项目技术选型的参考。

## 一、整体架构

```
音频输入 → 预处理 → ASR转写 → 说话人分离 → 情绪/语气识别 → 标签标注 → 质检审核 → 输出
```

各环节可独立替换，也可组合为端到端 Pipeline。

---

## 二、说话人识别 (Speaker Diarization)

### 2.1 核心技术：声纹嵌入 (Speaker Embedding)

将一段语音映射为固定维度向量，同一人向量距离近，不同人距离远。

| 架构 | 特点 | 适用场景 |
|------|------|----------|
| **x-vector** | 经典 TDNN + 统计池化，对噪音敏感，需较长语音段 | 早期系统，算力受限 |
| **ECAPA-TDNN** | 多尺度特征聚合 + SE 注意力，抗噪强，短语音表现好 | **当前工业界首选** |
| **RawNet3** | 端到端从原始波形学习，无需手工特征 | 研究型，特定场景 |

### 2.2 完整 Pipeline

```
1. VAD (语音活动检测)     → 剔除静音，保留人声
2. Segmentation (分段)    → 检测说话人切换点
3. Embedding (特征提取)   → ECAPA-TDNN 提取 192/256/512 维向量
4. Clustering (聚类)      → 余弦相似度 + 凝聚层次聚类
5. Scoring (优化)         → VBx 边界平滑
```

### 2.3 主流工具

| 工具 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| **pyannote.audio** | 生态最好，HF 集成，支持重叠语音检测 | 依赖 PyTorch，需申请 token | ⭐⭐⭐⭐⭐ |
| **NVIDIA NeMo** | 性能极致，支持流式，适合大规模部署 | 依赖 NVIDIA GPU，配置复杂 | ⭐⭐⭐⭐ |
| **SpeechBrain** | 模块化，易改模型结构 | 文档分散，工程化弱 | ⭐⭐⭐ |

### 2.4 常见问题与对策

| 问题 | 对策 |
|------|------|
| 两人同时说话 (Overlap) | 使用支持重叠检测的模型 (pyannote v3.1)，或端到端 EEND |
| 短语音碎片化 | 设最小语音时长阈值 (0.5s)，VAD 过滤非语音 |
| 说话人数量未知 | AHC + 阈值自动推断，或 EEND 端到端方案 |
| 跨音频一致性 | 建声纹库，1:1 或 1:N 匹配 |

## 三、情绪/语气识别 (Speech Emotion Recognition, SER)

### 3.1 技术路线

| 路线 | 说明 | 代表方案 |
|------|------|----------|
| **纯声学** | 从语音信号直接提取情绪特征 | Wav2Vec 2.0, HuBERT + 分类头 |
| **纯文本** | 从转写文本推断情绪 | BERT/RoBERTa + 情感分类 |
| **多模态融合** | 声学 + 文本联合判断，准确率最高 | Whisper + 文本模型融合 |
| **端到端大模型** | 多模态 LLM 直接输出 | Qwen-Audio, Mini-Omni |

### 3.2 声学特征

传统手工特征（仍广泛使用）：
- **MFCC**: Mel 频率倒谱系数，捕捉频谱包络
- **Pitch/F0**: 基频，反映语调高低
- **Energy**: 能量，反映音量/强度
- **Spectrogram**: 频谱图，CNN 输入
- **Prosody**: 韵律特征（语速、停顿、节奏）

### 3.3 主流模型

| 模型 | 特点 | 情绪类别 |
|------|------|----------|
| **Wav2Vec 2.0** | 自监督预训练，微调后效果好 | 6 类 (怒/喜/悲/惧/惊/中性) |
| **HuBERT** | 改进版 Wav2Vec，离散单元学习 | 同上 |
| **ESM (Emotion Speech Model)** | 专门针对情绪训练的模型 | 细粒度情绪 |
| **Whisper + 下游** | 用 Whisper 提取特征 + 分类头 | 自定义类别 |

### 3.4 语气识别 (非情绪)

语气与情绪不同，更关注说话方式：

| 语气类型 | 识别方法 |
|----------|----------|
| 疑问/陈述 | 文本句末标点 + 语调上升检测 |
| 命令/请求 | 文本意图分类 + 语气词检测 |
| 讽刺/反话 | 文本语义 + 声学不一致性（如正面词+负面语调） |
| 犹豫/不确定 | 填充词检测 (嗯、啊) + 停顿分析 |

## 四、标签标注

### 4.1 标注方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **人工标注平台** | Label Studio, Prodigy, Doccano | 高精度需求，小批量 |
| **LLM 预标注 + 人工校验** | 大模型自动生成，人工审核修正 | **当前最优性价比** |
| **规则引擎** | 关键词匹配 + 正则 + 决策树 | 简单场景，快速上线 |
| **主动学习** | 模型不确定性高的样本优先送人工 | 持续迭代优化 |

### 4.2 常见标签体系

| 维度 | 标签示例 |
|------|----------|
| **意图分类** | 咨询、投诉、建议、闲聊、命令... |
| **场景分类** | 餐厅点餐、会议讨论、课堂教学、客服... |
| **情感基调** | 正式、轻松、幽默、严肃、愤怒... |
| **人物关系** | 父子、同事、师生、客服与顾客... |
| **实体抽取** | 人名、地名、产品名、时间、金额... |
| **敏感内容** | 脏话、政治敏感、隐私泄露... |
| **业务自定义** | 根据具体业务场景定制 |

### 4.3 LLM 标注最佳实践

```
Prompt 设计原则：
1. 提供清晰的任务定义和输出格式
2. 给出 2-3 个示例 (few-shot)
3. 约束输出为结构化格式 (JSON)
4. 设置低 temperature (0.1-0.3) 保证稳定性
5. 对关键标签定义明确的判断标准
```

## 五、质量评估

### 5.1 ASR 质量评估

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **WER** (Word Error Rate) | 词错误率，需参考文本 | (插入+删除+替换) / 总词数 |
| **CER** (Char Error Rate) | 字错误率，中文更适用 | 同 WER，按字计算 |
| **UTMOS** | 无参考语音质量评分 | 神经网络预测 MOS 分 |
| **DNSMOS** | 微软出品，降噪质量评估 | 信号质量 + 噪声质量 + 整体 |

### 5.2 标注质量评估

| 方法 | 说明 |
|------|------|
| **多人交叉标注** | 同一份数据多人标注，计算 Kappa 系数一致性 |
| **抽检审核** | 随机抽取 10-20% 由资深审核员复核 |
| **行为指标** | 标注时长、修改次数、回退次数 |
| **LLM 辅助质检** | 用大模型校验标注结果合理性 |

### 5.3 标注一致性检验

```python
# Cohen's Kappa 系数
# κ = (Po - Pe) / (1 - Pe)
# Po = 实际一致率, Pe = 期望一致率
# κ > 0.8: 高度一致
# κ > 0.6: 中度一致
# κ < 0.4: 一致性差，需重新培训
```

## 十一、准确性与质量提升落地方案

> 结合本项目现状，将业界质量保障方案转化为可执行的实施计划。

### 11.1 ASR 质量可量化 — CER 指标

**现状差距**: 转写完成后缺少质量反馈，无法量化不同 backend 的表现差异。

**实现方案**:

| 项目 | 说明 |
|------|------|
| 触发时机 | 用户在 ResultsView 中人工修正转写文本后自动计算 |
| 指标 | CER (Character Error Rate)，中文场景比 WER 更合适 |
| 算法 | 编辑距离 (Levenshtein Distance)，`(插入+删除+替换) / 参考文本字数` |
| 实现位置 | `annotator.py` 新增 `calculate_cer()` 方法 |
| 数据积累 | 按 backend × 音频类型 存储 CER 历史，用于横向对比模型效果 |
| 工作量 | ~1 天 |

```python
# 核心实现（编辑距离）
def calculate_cer(hypothesis: str, reference: str) -> float:
    """计算字错误率 (Character Error Rate)"""
    import Levenshtein
    if not reference:
        return 0.0 if not hypothesis else 1.0
    distance = Levenshtein.distance(hypothesis, reference)
    return distance / len(reference)
```

**扩展**: 积累足够数据后，可生成 "ASR 质量报告"，帮助用户选择最佳 backend。

### 11.2 LLM 标注置信度 + 主动学习

**现状差距**: LLM 标注后人工审核是无差别审核，没有优先级，也没有形成反馈闭环。

**实现方案**:

#### A. 置信度输出

| GUI 展示 | ResultsView 中低置信度标签标红高亮，排序优先展示 |
| 实现位置 | `labeler.py` 修改 prompt + 解析逻辑，`ResultsView.svelte` 增加标红 |
| 工作量 | ~1 天 |

```json
// LLM 输出格式示例
{
  "labels": {
    "intent": { "value": "投诉", "confidence": 0.92 },
    "emotion": { "value": "愤怒", "confidence": 0.55 },
    "scene": { "value": "客服对话", "confidence": 0.88 }
  }
}
```

#### B. 人工修正数据回收（简化版主动学习）

```
LLM 标注 → 人工修正 → 保存修正对 (原始标签, 修正标签, 上下文)

```

| 项目 | 说明 |
|------|------|
| 存储 | 修正记录保存到 `corrections.jsonl`，每条包含原始/修正/上下文 |
| 分析 | 统计高频修正模式，识别 LLM 的系统性偏差 |
| 迭代 | 将典型修正 case 追加到 prompt 的 few-shot 示例中 |
| 实现位置 | `server.py` 的 `/api/save-annotations` 增加 diff 记录 |
| 工作量 | ~2 天 |

### 11.3 说话人分离升级 — pyannote.audio

**现状差距**: LLM 语义推断说话人依赖文本上下文，对纯声学特征（音色）无感知，多人同时说话时失效。

**实现方案**:

| 项目 | 说明 |
|------|------|
| 方案 | pyannote.audio v3.1 作为可选的说话人分离后端 |
| 架构 | 在 ASR 之后、LLM 标注之前插入说话人分离步骤 |
| 互补策略 | 声学分离给出 speaker_0/1/2 + LLM 推断给出角色名（如"客服"/"客户"） |
| 重叠语音 | pyannote v3.1 原生支持 Overlap Detection |
| 实现位置 | `src/audio_label/diarization/` 新建模块 |
| 依赖 | `pyannote.audio`, `torch`, HuggingFace token |
| 工作量 | ~1 周 |

```
Pipeline 调整：
音频 → ASR 转写 (带时间戳)
  ↓
音频 → pyannote 说话人分离 (speaker_id + 时间边界)
  ↓
合并：按时间戳对齐 ASR segments 与 speaker labels
  ↓
LLM 标注：结合说话人信息做角色识别和语义标注
```

**配置方式**: GUI Settings 中新增 "说话人分离" 开关，可选 "LLM 语义推断" 或 "pyannote 声学分离"。

### 11.4 音频预处理 — 降噪

**现状差距**: 原始音频直接送入 ASR，嘈杂环境下转写质量下降明显。

**实现方案**:

| 项目 | 说明 |
|------|------|
| 方案 | DeepFilterNet 作为可选预处理步骤 |
| 触发 | 用户可在 ConfigBar 中开启 "降噪预处理" 开关 |
| 流程 | 降噪后的音频写入临时文件 → 送入 ASR → 处理完成后清理临时文件 |
| 实现位置 | 新建 `src/audio_label/preprocessor.py` |
| 依赖 | `deepfilternet` |
| 工作量 | ~3 天 |

```python
# 预处理 Pipeline
class AudioPreprocessor:
    def __init__(self, denoise: bool = False):
        self.denoise = denoise

    def process(self, audio_path: Path) -> Path:
        if self.denoise:
            return self._apply_deepfilter(audio_path)
        return audio_path
```

**注意**: 降噪会改变音频特征，可能影响情绪识别等下游任务。建议保留原始音频用于声学分析，降噪版本仅用于 ASR。

### 11.5 标注一致性检验 — Kappa 系数

**现状差距**: 单人标注无一致性度量，无法评估标注规范是否清晰。

**实现方案**:

| 项目 | 说明 |
|------|------|
| 场景 A | 同一段音频，LLM 标注 vs 人工标注，计算 Cohen's Kappa |
| 场景 B | 同一段音频，不同 prompt/model 做两次 LLM 标注，评估 prompt 质量 |
| 阈值 | κ > 0.8 高度一致；κ > 0.6 可接受；κ < 0.4 需改进标注规范或 prompt |
| 实现位置 | 新建 `src/audio_label/metrics.py` |
| 工作量 | ~2 天 |

```python
def cohens_kappa(labels_a: list[str], labels_b: list[str]) -> float:
    """
    计算 Cohen's Kappa 系数
    κ = (Po - Pe) / (1 - Pe)
    Po = 实际一致率, Pe = 期望一致率（随机一致的概率）
    """
    assert len(labels_a) == len(labels_b)
    n = len(labels_a)
    categories = set(labels_a) | set(labels_b)

    po = sum(1 for a, b in zip(labels_a, labels_b) if a == b) / n

    pe = 0.0
    for cat in categories:
        p_a = labels_a.count(cat) / n
        p_b = labels_b.count(cat) / n
        pe += p_a * p_b

    if pe == 1.0:
        return 1.0
    return (po - pe) / (1 - pe)
```
