## Changes

### Phase 7: Memory System Enhancement (M1-M6)

- **M1 Auto-Extract**: `autoExtract()` and `autoExtractBatch()` analyze content for high-value signals (decisions, errors, solutions, insights) and automatically store qualifying content as semantic memory. Scoring combines keyword signals (up to 0.5), content length (up to 0.2), and specificity indicators like code paths and technical terms (up to 0.3).

- **M2 Auto-Organize**: `autoOrganize()` performs deduplication using trigram Jaccard similarity, merges tags/lessons from duplicates, and cleans up expired entries based on configurable TTL. Works on both semantic and episodic tiers.

- **M3 Memory Compression**: `compressMemories()` clusters related memories by tag overlap using union-find, then compresses each cluster into a single summary entry. Configurable min cluster size and max clusters per pass.

- **M4 Memory Decay**: `decayImportance()` applies exponential decay (half-life model) to importance scores. Entries with recent access get a "refresh" that slows decay. `recordAccess()` tracks retrieval frequency. `getDecayedEntries()` identifies entries below importance threshold for cleanup.

- **M5 Memory Graph**: `MemoryGraph` class builds associations between memories based on keyword overlap, shared tags, and temporal co-occurrence. Supports BFS-based `findRelated()` for linked retrieval and `findPath()` for shortest path between entries.

- **M6 Tests**: 28 tests covering all features — auto-extract scoring/threshold/batch, organize dedup/TTL, compression clustering, decay half-life/access-refresh/floor, graph relations/path/stats.
