# OpenVera v0.3.1 Release Notes

OpenVera v0.3.1 is a stability release focused on production build quality and reducing log noise.

## Changes

### Production Build Improvements

All package build scripts now inject `NODE_ENV=production`, ensuring the logger defaults to `info` level in published packages. Debug-level logs are suppressed unless explicitly enabled via `VERA_LOG_LEVEL=debug` or `NODE_ENV=development`.

### Logger Default Level

- **Default level changed from `debug` to `info`** — production installs no longer emit debug logs to stderr
- `NODE_ENV=production` → `info` level
- `NODE_ENV=development` → `debug` level
- No env set → `info` level (safe production default)
- Explicit override: `VERA_LOG_LEVEL=debug`

### Status Messages Routed Through Logger

Hardcoded `console.error` calls in the main entry point (`packages/core/src/main.ts`) have been replaced with proper logger calls, so status messages respect the configured log level.

### Previous Changes (from v0.3.0)

- Claude Code configuration migration
- `vera sync` command for resource syncing
- CLI aliases: `vera`, `ai` (in addition to `openvera`)
- Interactive first-run setup wizard
- Vera Control Gateway (monorepo)
- Improved provider/model switching reliability
- Gateway UI (Vue web + Node HTTP server)

## Installation

```bash
npm install -g @open-vera/openvera@0.3.1
```

Or run with:

```bash
npx @open-vera/openvera@0.3.1
```

Start the REPL:

```bash
ai
# or: vera, openvera
```

## Notes

- Gateway UI ships with the repository and is not yet published as a standalone npm package
- Use `ai`, `vera`, or `openvera` interchangeably — all three are aliases
- Set `VERA_LOG_LEVEL=debug` to see debug logs in development
