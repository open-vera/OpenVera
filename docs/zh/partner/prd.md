# Partner — 产品需求文档 (PRD)

> 版本：v0.6 · 2026-06-19 · 状态：草案

---

## 1. 产品概述

### 1.1 愿景

Partner 是一款基于 OpenVera 引擎的通用 AI Agent 桌面端应用。它不只是一个"对话框"——而是一个能自主规划、执行、反思、进化的本地智能伙伴。

### 1.2 一句话定义

> 一个运行在桌面上的 AI Agent，能理解你的意图，调用本地工具，完成复杂任务，并在过程中不断学习和改进。

### 1.3 设计哲学

**极简与自然**：没有会话列表、没有繁琐配置。三栏布局各司其职——左侧文件和 Git 变更，中间对话，右侧多标签预览面板（支持网页、PDF、图片、音视频、代码等）。上下文管理完全由引擎自动完成，用户无需感知。

### 1.4 核心差异化

| 维度 | 传统 AI 助手 | Partner |
|------|-------------|---------|
| 交互模式 | 单轮问答 | 多步自主执行 |
| 上下文 | 窗口有限，超出即丢 | 无限上下文，自动压缩与召回 |
| 工具能力 | 有限 API | 本地文件/Shell/浏览器/自定义工具 |
| 错误处理 | 报错即停 | 自主诊断 → 重试 → 求助 |
| 进化能力 | 无 | 自我批评 → 策略提案 → 基准验证 |
| 持久化 | 会话丢失 | 自动持久化，永远可回溯 |

## 2. 目标用户

### 2.1 用户画像

Partner 面向**所有人**，而不仅仅是技术人员。软件必须做到开箱即用，不需要任何技术背景。

| 画像 | 描述 | 核心需求 |
|------|------|---------|
| **普通用户**（主要） | 日常办公人员、学生、家庭用户 | 写东西、查资料、整理文件、自动化杂务 |
| **知识工作者** | 研究员、分析师、写作者、编辑 | 文档整理、数据处理、信息检索、内容创作 |
| **创业者/自由职业** | 小团队负责人、自由职业者 | 报告生成、客户沟通、项目管理、市场调研 |
| **开发者**（早期用户） | 程序员、运维工程师 | 代码生成、调试、自动化脚本 |

### 2.2 设计约束

> **核心原则**：对非技术用户来说，软件中不应出现任何需要理解的术语。
> 文件树、Git 变更、代码高亮等开发者功能作为**进阶能力**按需呈现，不干扰普通用户。

### 2.3 使用场景

| 场景 | 示例 | 面向 |
|------|------|------|
| 日常写作 | "帮我把这段话改得更正式一些" | 所有人 |
| 文件整理 | "把桌面上的照片按日期分到不同文件夹" | 所有人 |
| 信息搜索 | "帮我查一下去三亚旅游的最佳时间和预算" | 所有人 |
| 数据处理 | "分析这个 Excel，告诉我哪个月销量最高" | 办公人员 |
| 文档写作 | "根据这些笔记，整理出一份会议纪要" | 知识工作者 |
| 内容创作 | "帮我写一篇关于环保的公众号文章" | 创作者 |
| 学习辅助 | "用简单的话给我解释一下量子计算" | 学生 |
| 代码开发 | "帮我写一个脚本，批量重命名图片" | 开发者 |

## 3. 核心功能

### 3.1 P0 — 最小可用版本

#### 3.1.1 对话界面

- 单一对话流，无会话切换——打开即继续
- 聊天式交互，支持 Markdown 渲染与代码高亮
- 工具执行结果（成功/失败）直接在对话流中以内联卡片展示
- 工具调用详情默认折叠，点击展开
- 流式输出，实时显示 Agent 思考与执行过程

#### 3.1.2 多模态输入

对话是核心交互形式，天然支持多种输入方式：

| 输入方式 | 说明 |
|---------|------|
| 键盘输入 | 标准文字输入，支持多行编辑 |
| 语音输入 | STT 实时转文字，自然对话 |
| 文件拖入 | 拖拽文件/文件夹直接作为上下文 |

#### 3.1.3 全局搜索

- 搜索历史对话内容（全文检索）
- 搜索结果定位到对话流中的对应位置
- 无需会话列表——对话里发生的一切，搜一下就能找到

#### 3.1.4 无限上下文引擎

用户无需管理会话、上下文或记忆，一切由引擎自动完成：

```
┌──────────────────────────────────────────────────────┐
│                  无限上下文引擎                         │
│              (复用 OpenVera Core Context 模块)          │
│                                                      │
│  ┌──────────────────────────────────────────────┐    │
│  │  工作记忆 (Working Memory)                     │    │
│  │  最近 N 轮原文 + 原始任务锚点 → 直接送入 LLM    │    │
│  │  实现: context/window.ts — trimToWindow()      │    │
│  └──────────────┬───────────────────────────────┘    │
│                 │ 超阈值时自动触发压缩                  │
│  ┌──────────────▼───────────────────────────────┐    │
│  │  摘要记忆 (Summary Memory)                     │    │
│  │  分段压缩 → 结构化摘要注入                      │    │
│  │  (summary + decisions + findings + pending)    │    │
│  │  实现: context/compression.ts — compressMsg()  │    │
│  │  空闲压缩: context/idle-compression.ts          │    │
│  └──────────────┬───────────────────────────────┘    │
│                 │ 定期固化到持久化存储                   │
│  ┌──────────────▼───────────────────────────────┐    │
│  │  长期记忆 (Long-term Memory)                    │    │
│  │  SQLite 持久化 + 语义检索                       │    │
│  │  按相关性召回 → findRelevantSegments() 按需注入 │    │
│  │  实现: memory/memory-updater + storage/memory  │    │
│  └──────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

**现有 OpenVera Core 实现**：

| 层级 | 核心模块 | 机制 |
|------|---------|------|
| 工作记忆 | `context/window.ts` | `trimToWindow()` — 保留原始任务锚点 + 最近 N 轮，按 turn 粒度裁剪 |
| 摘要记忆 | `context/compression.ts` | 分段压缩，每段提取 summary/decisions/findings/pending/topics |
| 空闲压缩 | `context/idle-compression.ts` | 用户空闲时自动触发压缩（默认 314s），新用户输入可中断 |
| 工具预算 | `context/tool-budget.ts` | 控制单条工具结果体积，防止工具输出撑爆上下文 |
| 语义检索 | `compression.ts` | `findRelevantSegments()` — 从压缩段中按相关性召回 |

**Partner 复用策略**：

- P0 直接复用 `@open-vera/core/context` 模块，无需重新实现
- 如有必要，可将 context 模块抽象为独立的 **Context Manager Package**，供 Partner 和其他消费方共享
- 长期记忆层复用 `memory/memory-updater` + `storage/memory-adapter`，通过 SQLite 持久化

#### 3.1.5 Agent 执行引擎

- 基于 OpenVera Harness 运行时
- 支持自主规划 → 执行 → 批评 → 重规划循环
- 工具调用链可视化
- 执行预算控制（token / 步数 / 时间）

#### 3.1.6 本地工具集

| 工具 | 能力 |
|------|------|
| 文件读写 | 读取、创建、编辑本地文件 |
| Shell 执行 | 运行终端命令，支持超时和安全沙箱 |
| 代码搜索 | Glob / Grep 文件搜索 |
| 网页搜索 | 基于 AnySearch 统一搜索（见下文） |
| 浏览器 | 基于 Agent Browser 的网页操作（可选） |

#### 3.1.7 统一网页搜索

不使用模型自带的 Web Search，而是通过自建搜索技能提供一致的高质量搜索体验：

**方案**：AnySearch 聚合引擎 + Tavily Search + 百度搜索

**为什么不使用模型自带 Web Search**：

| 问题 | 说明 |
|------|------|
| 速度慢 | 模型原生搜索响应延迟高 |
| 效果不统一 | 不同模型/Provider 搜索结果差异大 |
| 质量参差不齐 | 搜索结果的准确性和相关性不稳定 |

**AnySearch 方案优势**：

- 统一接口，无论底层模型是哪个，搜索结果一致
- 聚合多源结果（Tavily Search + 百度搜索），覆盖面更广
- 作为 OpenVera 技能（Skill）实现，可独立迭代和优化
- 搜索质量可控，可针对中文场景优化

#### 3.1.8 LLM 配置

- 开箱即用：提供默认的推荐模型，用户只需输入 API Key 即可开始
- 支持多 Provider（Anthropic / OpenAI）
- 进阶用户可自由切换模型
- 仅在线 API，暂不支持离线模型

### 3.2 P1 — 增强体验

#### 3.2.1 多实例编排与任务看板

- 本地多 Agent 实例并行执行，由编排层统一调度
- 任务自动分解与分发，实例间结果汇总与冲突解决
- **任务看板**：应用内入口，可视化展示**所有窗口（会话）**的任务进展
  - 待办 / 进行中 / 已完成 三列看板
  - 每个任务卡片显示：任务描述、所属窗口、分配的实例、进度、耗时
  - 点击任务卡片可跳转到对应的窗口/对话上下文
- 网关层聚合所有实例状态，提供统一的进展查询接口

#### 3.2.2 通知与确认

- 高风险操作确认弹窗
- 长任务完成系统通知

### 3.3 P2 — 进阶能力

#### 3.3.1 插件系统

- 用户自定义工具注册
- 插件市场（本地/社区）
- 安全沙箱隔离

#### 3.3.2 多模态增强

- 图片理解（截图分析、图片内容识别）

#### 3.3.3 自进化仪表盘

- 执行成功率趋势
- 工具使用统计
- Critique 改进建议回顾

### 4.2 多实例 + 单进程编排架构

Partner 采用**单桌面进程 + 多 Agent 实例**的架构：

| 层 | 职责 |
|----|------|
| **桌面进程（父进程）** | 唯一的 GUI 进程，承载 UI 渲染、用户交互、任务编排 |
| **编排层 (Orchestrator)** | 任务队列管理、实例生命周期、任务分发与结果汇总 |
| **网关层 (Gateway)** | 聚合所有实例/会话的状态，提供统一的任务进展视图 |
| **Agent 实例** | 独立的执行单元，每个实例运行自己的 Core + Harness + Tools |

**隐式会话模型**：

> 对用户来说，不存在"会话"这个概念。用户通过双击启动、右键新建窗口等方式打开一个新窗口，系统自动将其视为一个独立的对话会话。一切由编排层自动管理。

- 每个窗口 = 一个隐式会话 = 一个 Agent 实例
- 用户无需手动创建/切换/管理会话
- 编排层自动跟踪所有窗口的任务状态
- 看板聚合展示所有窗口（会话）中的任务进展

**工作流**：
1. 用户打开窗口，自然对话下达任务
2. 编排层自动将窗口映射为 Agent 实例
3. 复杂任务可进一步分解为子任务，由多个实例并行执行
4. 网关层实时汇总所有窗口/实例的进度
5. 看板 UI 展示全局任务状态（跨所有窗口）

### 4.3 技术栈

| 层 | 技术选型 | 说明 |
|----|---------|------|
| 前端 UI | Vue 3 + TypeScript | 标准客户端界面，Composition API |
| 构建工具 | Vite | 与 gateway-ui 统一，Tauri 官方支持 |
| 桌面框架 | Tauri 2.0 | Rust 后端，包体小（~5MB），原生性能 |
| 状态管理 | Pinia | Vue 官方推荐，TypeScript 友好 |
| 样式 | UnoCSS 或 Tailwind CSS | 原子化 CSS，快速开发 |
| Markdown | markdown-it + highlight.js | 对话气泡中的渲染与代码高亮 |
| Agent 引擎 | OpenVera Core (WASM) | 编译为 WASM，Rust 直接调用 |
| 存储 | SQLite (via Tauri) | 本地对话/记忆持久化 |
| LLM 连接 | OpenVera Adapters | 支持 Anthropic / OpenAI |

**选型依据**：OpenVera 现有 gateway-ui 已使用 Vue 3 构建，团队具备 Vue 开发经验。OpenVera Core 引擎层为纯 TypeScript，与前端框架完全解耦，通过 Tauri IPC 桥接，无框架绑定。

### 4.4 与 OpenVera 的集成方式

```
Partner (Tauri App)
    │
    └── Tauri Rust Core 直接调用 OpenVera WASM 模块
        └── 零进程开销，内存共享，调用延迟 < 1ms
```

**方案**：将 OpenVera Core 编译为 WASM，由 Tauri Rust 层直接调用。相比子进程方案，省去 IPC 序列化开销，启动更快，内存占用更低。

### 4.5 安全设计

| 风险 | 对策 |
|------|------|
| Shell 注入 | 命令白名单 + 参数转义 + 用户确认 |
| 文件越权 | 沙箱目录限制 + 路径规范化 |
| API Key 泄露 | 优先系统 Keychain（Win Credential Manager / macOS Keychain），回退本地文件 AES-256-GCM 加密 |
| 恶意插件 | 四层防护：权限声明(manifest) + 安装确认弹窗 + Worker 线程沙箱隔离 + 网络 Host 白名单 |

**插件安全模型详细设计**：

| 层级 | 机制 | 说明 |
|------|------|------|
| 权限声明 | `PluginPermissions`（manifest.json） | 声明 fs/网络/环境变量/工具访问权限 |
| 安装确认 | 安装时展示权限摘要 | 类似移动端权限弹窗，用户明确授权 |
| 运行时隔离 | Worker 线程沙箱 | 插件在独立 Worker 中运行，message channel 通信 |
| 网络隔离 | Host 白名单 + Tauri HTTP 代理 | 所有网络请求经网关层过滤 |
| 完整性校验 | `PluginLockfile` checksum | 防止插件文件篡改 |

**WASM 编译策略**：

| 模块 | 策略 | 原因 |
|------|------|------|
| `context/` `agent/` `prompt/` `plan/` `intent/` `types/` | **编译 WASM** | 纯逻辑，无 IO 依赖 |
| `adapters/` (LLM SDK) | **保留 JS** | HTTP SDK 依赖，走 Tauri HTTP 调用 |
| `storage/` (SQLite) | **保留 JS** | Native 依赖，用 Tauri SQLite 替代 |
| `tools/` | **保留 JS** | 工具执行需 Node.js 环境 |
| `repl/` | **不需要** | Partner 使用 Vue UI，无终端渲染需求 |

## 5. UI/UX 设计

### 5.1 主界面布局

三栏设计——左侧文件与变更，中间对话，右侧按需预览：

```
┌─────────┬────────────────────────────────┬──────────────┐
│         │                                │              │
│ 文件树   │        对话流（核心）           │  预览面板     │
│         │                                │  (多标签)    │
│ 📁 src  │  👤 帮我重构这个模块           │              │
│  ├ a.ts │                                │ ┌──────────┐ │
│  ├ b.ts │  🤖 好的，我来看看...          │ │ preview  │ │
│  └ c.ts │  ┌─ 🔧 工具调用 ────────────┐  │ │ .html    │ │
│         │  │ Edit: src/a.ts            │  │ │ report   │ │
│         │  │ ✅ 成功                   │  │ │ .pdf     │ │
│─────────│  └──────────────────────────┘  │ │ logo.png │ │
│ Git 变更 │                                │ └──────────┘ │
│         │  已完成重构，主要改动：         │              │
│ M a.ts  │  - 拆分了 xxx 模块             │  [HTML][PDF] │
│ M b.ts  │  - 新增了 yyy 接口             │  [PNG][Code] │
│ + d.ts  │                                │              │
│         │                                │              │
├─────────┴────────────────────────────────┴──────────────┤
│  [🎤/💬 输入消息... 或拖入文件]                  [发送]   │
└─────────────────────────────────────────────────────────┘
```

**各栏职责**：

| 栏位 | 职责 | 出现条件 |
|------|------|---------|
| **左侧 — 文件树** | 展示当前加载的文件夹结构 | 用户/Agent 打开项目文件夹时 |
| **左侧 — Git 变更** | 展示文件的修改/新增/删除状态 | 文件夹为 Git 仓库时 |
| **中间 — 对话流** | 核心区域，消息流与工具执行结果 | 始终显示 |
| **右侧 — 预览面板** | 多标签页通用预览，支持各类文件 | 有内容需要预览时 |

> 对于普通用户，日常使用时界面只有**中间对话流 + 按需预览**，左侧栏不会出现。
> 文件树和 Git 变更仅在涉及开发项目时自然浮现，不增加普通用户的认知负担。

**右侧预览面板支持的格式**：

| 类型 | 格式示例 | 说明 |
|------|---------|------|
| 网页 | HTML / URL | 内置浏览器，预览页面效果 |
| 文档 | PDF / Markdown | 渲染展示文档内容 |
| 图片 | PNG / JPG / SVG | 图片查看器 |
| 音视频 | MP4 / MP3 / WAV | 内嵌播放器 |
| 代码 | 各类源码文件 | 语法高亮查看 |

预览面板为**多标签页**设计——Agent 生成或打开了多个文件时，可以同时打开多个预览标签，方便对比和检查。

**输入区域**（底部固定）：

- 支持键盘打字输入
- 支持语音输入（麦克风按钮）
- 支持文件/文件夹拖入作为上下文
- 首次打开时极简引导（选择模型 + 输入 API Key），之后不再打扰

### 5.2 交互原则

| 原则 | 说明 |
|------|------|
| 极简自然 | 像聊天软件一样，打开就继续聊，无需任何切换 |
| 渐进披露 | 默认折叠细节，点击展开完整工具输出 |
| 实时反馈 | 流式输出，工具执行状态实时更新 |
| 可中断 | 随时停止 Agent 执行 |
| 最小惊讶 | 高风险操作必须确认，结果可预期 |

### 5.3 主题

- 深色模式（默认）
- 浅色模式
- 跟随系统

## 8. 已决策事项

| # | 问题 | 决策 |
|---|------|------|
| 1 | OpenVera 集成方式 | WASM 直接调用，Rust 层零开销桥接 |
| 2 | 离线模型支持 | 暂不支持，仅在线 API |
| 3 | 账号体系 | 暂不需要，纯本地 API Key 配置 |
| 4 | 数据同步 | 暂不需要，单设备本地存储 |
| 5 | 前端框架 | Vue 3（项目已有 Vue 实践，与引擎解耦） |
| 6 | UI 风格 | 标准客户端界面，非终端风格 |
| 7 | 交互范式 | 单一对话流 + 自动无限上下文，无显式会话管理 |
| 8 | 执行状态展示 | 不单独展示，执行结果直接在对话流内联显示 |
| 9 | 历史内容查找 | 全局搜索，不需要会话列表 |
| 10 | 界面布局 | 三栏设计：左文件/Git、中对话、右多标签预览面板（按需） |
| 11 | 输入方式 | 键盘 + 语音 + 文件拖入，作为 P0 天然支持 |
| 12 | 目标用户 | 面向所有人，非技术人员为主要群体，开发者为早期用户 |
| 13 | 简易性原则 | 界面不出现技术术语，开发者功能按需浮现，开箱即用 |
| 14 | 网页搜索 | 不使用模型自带 Web Search，采用 AnySearch + Tavily/百度搜索统一方案 |
| 15 | 无限上下文实现 | 复用 OpenVera Core Context 模块（分段压缩 + 最近全量），不重新实现 |
| 16 | 进程模型 | 单桌面进程（父进程）+ 多 Agent 实例，编排层自动调度 |
| 17 | 会话模型 | 隐式会话——用户不可见，每个窗口自动映射为一个会话/实例 |
| 18 | 任务可见性 | 网关层聚合状态 + 应用内任务看板，跨窗口查看所有任务进展 |
| 19 | 插件安全 | 权限声明(manifest) + 安装确认 + Worker 沙箱隔离 + 网络白名单 |
| 20 | API Key 存储 | 优先系统 Keychain，回退本地文件 AES-256-GCM 加密 |
| 21 | WASM 编译 | 纯逻辑层(context/agent/prompt/plan)编译 WASM，IO 层保留 JS 走 Tauri IPC |
