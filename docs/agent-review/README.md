# Agent Review

本目录用于沉淀 agent 在真实开发、合并、启动验证、问题修复中的 review case。

目标不是记录流水账，而是把可复用的判断、排查路径和修复原则留下来，方便后续遇到类似问题时快速定位。

## 记录规范

每个 case 建议包含：

- **现象**：用户看到了什么、命令输出是什么。
- **上下文**：当时的配置、分支、触发路径。
- **根因**：尽量落到具体模块、函数或状态流。
- **解决方案**：说明代码改动和取舍。
- **验证**：列出运行过的测试、启动验证或未覆盖风险。
- **经验沉淀**：抽象成下一次可复用的规则。

## Review 原则

- 先确认用户可见问题，再追溯内部状态。
- 配置正确时，优先怀疑控制流和默认行为，不把问题归因给用户配置。
- 降级逻辑不应该污染对话历史；用户可见消息必须有明确行动价值。
- 对无收益的 LLM 调用做短路，减少成本、延迟和失败面。
- 测试要覆盖触发条件、降级行为和用户可见结果。
